# Сервис планирования маршрутов инженеров — версия 2

Доказательный прототип для распределения заявок, контроля фактического исполнения смены и ограниченного оперативного перепланирования маршрутов выездных инженеров.

## Как запустить локально

### Windows

1. Откройте папку проекта.
2. Запустите файл `start-local.cmd` двойным щелчком.
3. Откройте в браузере `http://127.0.0.1:4173`.
4. Для остановки нажмите `Ctrl+C` в окне запуска.

Нужен Python 3. Устанавливать библиотеки не требуется. Для фоновой карты и чтения XLSX при первом запуске нужен доступ в интернет.

### macOS или Linux

```bash
python3 -m http.server 4173 --directory dist
```

После запуска откройте `http://127.0.0.1:4173`.

## Быстрый демонстрационный сценарий

1. Нажмите **Настроить параметры смены**.
2. При необходимости загрузите заявки и файл инженеров `examples/Инженеры.xlsx`. Нормативы уже зафиксированы как стандартный справочник.
3. Задайте порог автопересчёта и нажмите **Рассчитать план**.
4. Нажмите карточку **Инженеры в плане**, чтобы открыть список сотрудников, графики отставания и планы заявок.
5. Откройте план инженера. Из этого окна доступно **Ручное перепланирование**.
6. Нажмите любую точку на реальной карте, чтобы увидеть заявку, адрес, интервал и исполнителя.
7. Нажмите **Новое событие** и добавьте аварийную заявку либо измените статус инженера: снимите его с линии или верните обратно.
8. Откройте **Не распределено**. Сервис покажет всех инженеров, а недопустимые варианты сделает неактивными с объяснением причины.
9. В ручном перепланировании разрешите пересечение интервалов — карточка **Перегружено специалистов** сразу обновится.

## Реализованные возможности

- настоящий priority-aware regret-2: для каждой заявки считаются две лучшие допустимые вставки `c1`, `c2` и `regret = c2 − c1`;
- multi-start сравнивает regret-2 и first-fit seed, затем применяет 2-opt, relocate и swap только при улучшении допустимого плана;
- автоматически рассчитанная таблица `first-fit baseline → итоговый алгоритм` на одинаковых данных;
- единая матрица OSRM для времени переезда, расстояния, назначения и KPI пробега;
- фактические статусы `не начата / в пути / начата / завершена` и ввод фактического времени;
- накопленное отставание рассчитывается по факту завершения, а не по заранее заданной линии;
- оперативное перепланирование фиксирует заявки по фактическому статусу, а не по плановому времени;
- hard constraints нельзя обойти ручным назначением; временное наложение требует причины и записывается в журнал;
- quality gate отклоняет дубликаты, пропуски, неизвестную географию и неверные интервалы с указанием строки;
- объяснение назначения показывает ограничения, дорожный перегон и ближайшую совместимую альтернативу;
- воспроизводимый stress-test `до → выпадение инженера и авария → после` с рассчитанными KPI;
- корректный процент распределения: `назначено / всего × 100`;
- загрузка заявок из CSV, XLSX или JSON;
- загрузка инженеров из XLSX;
- неизменяемый стандартный справочник нормативов;
- ручной и автоматический пересчёт при превышении накопленного отставания;
- график накопленного отставания по инженерам;
- реальные картографические тайлы OpenStreetMap, маршруты по дорожному графу, кликабельные точки и карточки заявок;
- детальный план каждого инженера;
- регистрация новой аварийной заявки, снятие инженера с линии и его возврат;
- счётчик новых заявок;
- показатели свободного ресурса и числа перегруженных специалистов;
- изменение текущего времени для эмуляции хода смены;
- подробные списки по распределению и пробегу, матрицы свободных окон и наложений;
- подписи и подсказки со значениями на графике накопленного отставания;
- фильтрация списка и карты по рискам и резерву;
- оценка рисков и изменений относительно оптимального плана при ручном перепланировании;
- объяснение исключения каждого инженера из ручного назначения;
- адаптивный интерфейс.

## Логика распределения версии 2

1. Данные проверяются и нормализуются.
2. Для каждой пары «заявка — инженер» проверяются доступность, навык, транспорт, смена и временное окно.
3. Рассчитывается критичность `K = B + W + S + D + T`.
4. Для каждой заявки рассчитываются две лучшие допустимые вставки на основе одной дорожной матрицы.
5. Выбирается заявка с максимальным regret, при равенстве учитывается критичность.
6. Multi-start сохраняет лучший допустимый seed по лексикографической цели: сначала число назначений, затем пробег.
7. Локальный поиск проверяет перестановки 2-opt, relocate и swap без нарушения окон, смен, навыков и транспорта.
8. Если вставки нет, заявка получает объяснимую причину нераспределения.
9. Ручное назначение блокируется при нарушении hard constraints. Только временное наложение допускается с обязательным обоснованием.

В момент старта смены применяется **«Утреннее распределение»**. Позднее применяется **«Оперативное перепланирование»**: фиксируются заявки с фактическим статусом `в пути`, `начата` или `завершена`; перераспределяются только не начатые и новые заявки.

Свободный ресурс показывается в часах и минутах. Для построения пути по дорогам используется открытый маршрутизатор OSRM; если он временно недоступен, интерфейс сохраняет работоспособность и показывает резервную прямую линию.

## Накопленное отставание

```text
отклонение = фактическое окончание − плановое окончание
накопленное отставание = сумма отклонений по завершённым заявкам
```

Например, `+5`, `+1` и `−2` минуты дают итоговое отставание `4` минуты.

## Ограничения прототипа

- данные и журнал хранятся в текущей вкладке браузера;
- фон карты и дорожные маршруты требуют доступа в интернет; при недоступности сервиса маршрутизации используется прямая линия;
- координаты демонстрационных адресов заданы в покрытом справочнике районов; строки с неизвестным районом отклоняются quality gate;
- промышленная версия потребует серверного журнала событий, геокодирования, матрицы времени пути, авторизации и серверного оптимизатора.

Исторический бизнес-эффект, P95 на 500+ заявках и интеграционные показатели намеренно не выдуманы: для них нужны корпоративные исторические данные и промышленный контур.
