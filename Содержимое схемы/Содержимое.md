# Содержимое файла «Распределение заявок — обновлённый алгоритм»

Исходник — несжатый XML-файл draw.io, содержащий две страницы. Ниже извлечены все содержательные подписи блоков; надписи ветвей «Да» и «Нет» сохранены в отдельных файлах схем.

## 1. Утреннее распределение

- Нажатие кнопки "Планирование"
- 1. Система получает данные
- 2. Данные по заявкам
- 3. Проверка корректности данных (наличие обязательных полей, существуют ли указанные адреса)
- 4. Отсекаем некорректные. Маркируем, прописываем причину
- 5. Геокодирование адреса
- 6. Данные справочника с нормативами
- 7. Данные по инженерам (компетенции, график, оборудование)
- 8. Проверка корректности данных (есть ли график)
- 9. Отсекаем некорректные (если не заполнен график). Маркируем, прописываем причину
- 10. Проверить каждую пару: заявка-инженер на совпадение параметров: компетенции, техника, график-окно
- У каждой заявки есть инженер?
- 11. Отсекаем нераспределенные заявки. Маркируем и указываем причину
- 12. Рассчитать критичность K = B + W + S + D + T: бизнес-приоритет, узость окна, дефицит инженеров, длительность, технологическая сложность
- 13. Сформировать начальные маршруты методом priority-aware regret-2 insertion: сравнить лучшую и вторую допустимые вставки
- 14. Совместно оптимизировать все маршруты: relocate, 2-opt, переносы между инженерами, swap, 2-opt*, цепочки
- 15. Проверить жёсткие ограничения и целевую функцию: окна, смены, навыки, транспорт, число инженеров, пробег и объяснимость
- 16. Сформировать маршруты, плановые времена, загрузку, пробег, резервы, значения метрик и список исключений с причинами
- Есть нарушения или найдено улучшение?
- Диспетчер утвердил?
- 17. Вывести все маршруты и исключенные заявки на проверку диспетчеру
- 18. Зафиксировать ручные корректировки и провести расчет
- Опубликовать задания
- Методика блока 12
  B: авария 100; нет линка/разрывы 80; иная локальная 65; новое подключение 50; иное подключение 45; дозаказ 30; информация 20.
  W: окно ≤1 ч +10; ≤2 ч +5.
  S: 1/2/3/4+ кандидата = 25/15/8/0.
  D: ≥180/120–179/60–119/<60 мин = 15/10/5/0.
  T: гигабит +10; FTTB +5. Все веса настраиваемые.
- Лексикографическая цель блоков 14–15
  0. Нет нарушений жёстких ограничений.
  1. Максимум назначенных заявок.
  2. Максимум приоритета/критичности.
  3. Минимум задействованных инженеров.
  4. Минимум общего и индивидуального пробега.
  5. Минимум времени в пути, ожидания и дисбаланса.
  6. После публикации — минимум изменений плана.

## 2. Корректировка маршрутов

- Старт перепланирования
- Это авария?
- Отмена заявки?
- Пропал инженер со смены?
- 1. Система получает данные
- 2. Данные по заявкам
- 3. Проверка корректности данных (наличие обязательных полей, существуют ли указанные адреса)
- 4. Отсекаем некорректные. Маркируем, прописываем причину
- 5. Геокодирование адреса
- 6. Данные справочника с нормативами
- 7. Получить актуальные маршруты. Зафиксировать текущее время, положение, статусы и выполненную часть
- 8. Отобрать подходящих инженеров: навыки, транспорт, смена и достижимость окна
- 9. Пересчитать критичность и допустимые вставки для незавершённых и новых заявок
- 10. Проверить локальную priority-aware regret-2 вставку: дорога + остаток текущей работы + норматив аварии
- 11. Если локальной вставки недостаточно, перепланировать незавершённую часть по блокам 12–15; выполненные и начатые работы зафиксированы
